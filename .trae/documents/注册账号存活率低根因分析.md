# 注册账号存活率低 — 根因分析

## 一、核心结论

**"注册成功但短期失效"的首要根因是一个代码级指纹漂移 bug,而非环境因素。**

注册流程(`PlatformRegistrar`)持久化了 `device_id` 和 `fingerprint_profile` 两个字段,但实际 API 调用流程(`OpenAIBackendAPI`)读取的是 `fp` dict 和 `oai-device-id` 等**完全不同的字段名**,导致每次调用时:

| 指纹维度 | 注册时(正确) | API 调用时(bug) | 后果 |
|---|---|---|---|
| device_id | 固定持久化值 | **每次随机 `new_uuid()`** | 同账号跨设备 |
| User-Agent | Chrome 145/131/124/120 | **Edge 143(硬编码)** | UA 漂移 |
| TLS impersonate | chrome/chrome131/chrome124/chrome120 | **chrome110(硬编码)** | TLS 与 UA 矛盾 |
| sec-ch-ua | Chrome | **Edge 143(硬编码)** | Client Hints 矛盾 |
| Accept-Language | `en-US,en;q=0.9` | **`zh-CN,zh;q=0.9...`(硬编码)** | 语言暴露 |
| oai-did cookie | 带 | **缺失** | 设备 cookie 漂移 |

OpenAI 在注册后**第一次** `fetch_remote_info`(注册成功后立即调用,见 [openai_register.py:662](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L662))就能判定"同 access_token,数分钟内浏览器指纹 100% 翻转" → 触发 `app_session_terminated` / `invalid_grant`。

前一轮方案(`提高注册账号存活率方案.md`)只修复了**注册/重登/保活**三个流程的指纹一致性,却**完全遗漏了最高频的 API 调用流程**(`OpenAIBackendAPI`)。这是存活率仍低的根本原因。

## 二、致命根因:`OpenAIBackendAPI` 字段名不匹配(首要技术根因)

### 2.1 注册持久化的字段名

[openai_register.py:640-650](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L640-L650):
```python
return {
    "email": email,
    "password": password,
    "access_token": ...,
    "refresh_token": ...,
    "id_token": ...,
    "source_type": "web",
    "created_at": ...,
    "device_id": self.device_id,              # ← snake_case "device_id"
    "fingerprint_profile": self.profile.name,  # ← 字符串 "chrome131_win",非 dict
}
```

注册流程本身指纹完全正确:[openai_register.py:476-477](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L476-L477) 设 `oai-did` cookie,[openai_register.py:445](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L445) 设 `oai-device-id` 头,[openai_register.py:426](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L426) 用 `profile.impersonate`。

### 2.2 API 调用读取的字段名(不匹配)

[openai_backend_api.py:246-273](file:///d:/GithubProject/chatgpt2api/services/openai_backend_api.py#L246-L273) `_build_fp`:
```python
def _build_fp(self) -> Dict[str, str]:
    account = self.account
    raw_fp = account.get("fp")          # ← 读 "fp" dict,注册从没存过这个字段!永远 None
    fp = {...} if isinstance(raw_fp, dict) else {}   # ← 永远走 {} 分支
    for key in (
            "user-agent",               # ← 读 account["user-agent"],注册没存
            "impersonate",              # ← 读 account["impersonate"],注册没存
            "oai-device-id",            # ← 读 account["oai-device-id"],注册存的是 "device_id"!
            "oai-session-id",
            "sec-ch-ua",                # ← 读 account["sec-ch-ua"],注册没存
            ...
    ):
        value = str(account.get(key) or "").strip()   # ← 全部取不到值
        if value:
            fp[key] = value
    fp.setdefault("user-agent", "...Chrome/143...Edg/143...")  # ← 兜底 Edge 143
    fp.setdefault("impersonate", "chrome110")                   # ← 兜底 chrome110
    fp.setdefault("oai-device-id", new_uuid())                  # ← 兜底每次随机 UUID!
    fp.setdefault("sec-ch-ua", '"Microsoft Edge";v="143"...')   # ← 兜底 Edge 143
    ...
```

**字段名映射关系(关键证据)**:

| 注册持久化的 key | `_build_fp` 读取的 key | 是否匹配 |
|---|---|---|
| `device_id` | `oai-device-id` | **❌ 不匹配** |
| `fingerprint_profile`(字符串) | `fp`(期望 dict) | **❌ 不匹配** |
| 无 | `user-agent` | **❌ 注册没存** |
| 无 | `impersonate` | **❌ 注册没存** |
| 无 | `sec-ch-ua` | **❌ 注册没存** |

结果:`fp` dict 永远为空,所有字段走 `setdefault` 兜底默认值——**Edge 143 UA + chrome110 TLS + 随机 device_id**。

### 2.3 `__init__` 中还有更多硬编码矛盾

[openai_backend_api.py:195-220](file:///d:/GithubProject/chatgpt2api/services/openai_backend_api.py#L195-L220):

**额外矛盾点**:

- `Accept-Language` / `OAI-Language` 硬编码 `zh-CN` —— 注册统一 `en-US`。
- **无 `oai-did` cookie** —— 注册时 [openai_register.py:476-477](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L476-L477) 设了,API 调用完全没设。

### 2.4 触发时机:注册后立即失效

[openai_register.py:660-664](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L660-L664):
```python
account_service.add_account_items([result])
refresh_result = account_service.refresh_accounts([access_token])  # ← 注册后立即调用
```

`refresh_accounts` → `fetch_remote_info`([account_service.py:1321-1361](file:///d:/GithubProject/chatgpt2api/services/account_service.py#L1321-L1361))→ `OpenAIBackendAPI(access_token)` → 立即用错误指纹请求 `/backend-api/me`、`/backend-api/conversation/init`、`/backend-api/accounts/check`。

**即:注册成功后数秒内,系统自己就用"Edge 143 + 中文 + 随机 device + 无 oai-did"的指纹触发了第一次风控扫描。** 这是"短期失效"的直接诱因。

### 2.5 影响范围

`OpenAIBackendAPI` 是所有实际业务调用的入口:
- 对话/补全([conversation.py:729](file:///d:/GithubProject/chatgpt2api/services/protocol/conversation.py#L729) `text_backend()`)
- 图片生成(同文件)
- 账号信息拉取(`fetch_remote_info`)
- 限流检测

即:账号一旦入池被选中,每次调用都在用错误的指纹。

## 三、次要技术根因(放大失效)

### 根因 2:Codex 图片端点完全裸奔(高)

[openai_backend_api.py:600-604, 807-812, 855](file:///d:/GithubProject/chatgpt2api/services/openai_backend_api.py#L600-L604):
```python
def _codex_responses_headers(self) -> Dict[str, str]:
    return {
        "Authorization": f"Bearer {self.access_token}",
        "Content-Type": "application/json",
        # 只有这两项!无 UA、无 OAI-Device-Id、无 sec-ch-ua、无 Origin/Referer
    }
...
request = urllib.request.Request(...)  # ← 用 urllib,完全绕过 curl_cffi session!
with urllib.request.urlopen(request, timeout=timeout_secs) as raw:  # ← 无 TLS 指纹、无代理、无 cookie
```

Codex 图片端点用标准库 `urllib`,**绕过 `self.session`(curl_cffi)**,导致:
- 无 TLS 指纹伪装(urllib 的 JA3 是 Python 标准库特征,极易识别)
- 无 `account.proxy` 代理
- 无 `OAI-Device-Id`、`oai-did` cookie、`User-Agent` 等全部浏览器头

每次图片生成都是一次"裸奔 Python 请求",与注册指纹 0% 重合。

### 根因 3:token 刷新/保活请求头过简(中)

[account_service.py:373-386](file:///d:/GithubProject/chatgpt2api/services/account_service.py#L373-L386):
```python
response = session.post(
    self._OAUTH_TOKEN_URL,
    headers={
        "Accept": "application/json",
        "Content-Type": "application/x-www-form-urlencoded",
        "User-Agent": profile.user_agent,   # ← UA 正确(读了 fingerprint_profile)
        # ⚠️ 缺失:oai-did cookie、oai-device-id 头、sec-ch-ua-*、sec-fetch-*、origin、referer
    },
    ...
)
```

保活流程**正确读取了 `fingerprint_profile`**(UA、impersonate 一致),但**缺失 `oai-did` cookie 和 `oai-device-id` 头**。OpenAI 的 refresh_token 接口能对比注册时设备指纹与刷新时设备指纹,cookie 缺失会触发 token 失效。

### 根因 4:重登用全局代理而非账号代理(中,潜在)

[account_service.py:621](file:///d:/GithubProject/chatgpt2api/services/account_service.py#L621):
```python
proxy = config.get_proxy_settings()   # ← 全局代理,不读 account.proxy!
```

对比保活([account_service.py:371](file:///d:/GithubProject/chatgpt2api/services/account_service.py#L371))和 `OpenAIBackendAPI`([openai_backend_api.py:190-194](file:///d:/GithubProject/chatgpt2api/services/openai_backend_api.py#L190-L194))都走 `proxy_settings.build_session_kwargs(account=account, ...)`,唯独密码重登不走。当前无代理时影响小,但引入代理后会出现出口 IP 漂移。

### 根因 5:注册代理未持久化(中,潜在)

[openai_register.py:640-650](file:///d:/GithubProject/chatgpt2api/services/register/openai_register.py#L640-L650) result dict **无 `proxy` 字段**。注册用的 `self.proxy` 没写入账号,导致 `account.proxy` 永远为空,保活/重登/API 调用都回退全局代理。当前无代理时不影响,但引入代理后会与注册出口 IP 不一致。

### 根因 6:invalid_grant 无专门处理(低)

[account_service.py:468-469](file:///d:/GithubProject/chatgpt2api/services/account_service.py#L468-L469) 自动重登**仅匹配** `app_session_terminated`,`invalid_grant` 不触发清理。失效账号滞留池中反复失败,增加风控信号。

## 四、环境信誉因素(次要,非根因)

用户反馈:无代理(机房 IP)+ 临时邮箱为主。这两个因素确实存在,但:

1. **它们是"放大器"而非"主因"**。即使有住宅代理和真实邮箱,只要根因 1(`OpenAIBackendAPI` 字段名不匹配)存在,账号仍会在第一次 API 调用时因指纹翻转而失效。
2. **优先级判断**:修复根因 1 是纯代码改动、零成本、立即生效;而引入住宅代理池和切换 Outlook 邮箱池是运维成本高、见效慢的改动。应**先修代码 bug,再优化环境**。
3. 机房 IP + 临时邮箱主要影响"注册成功率"和"长期存活",但用户反馈是"短期失效"(数小时内),这更符合"指纹翻转触发即时风控"的特征。

## 五、根因优先级矩阵

| 根因 | 类型 | 影响程度 | 与"短期失效"关联度 | 修复成本 | 优先级 |
|---|---|---|---|---|---|
| 1. `OpenAIBackendAPI` 字段名不匹配 | 代码 bug | 致命 | 直接(注册后第一次调用即触发) | 低(改 `_build_fp`) | **P0** |

| 4. 重登代理不一致 | 代码 bug | 中 | 潜在 | 低 | **P1** |
| 5. 注册代理未持久化 | 代码 bug | 中 | 潜在 | 低 | **P1** |
| 6. invalid_grant 处理 | 代码缺陷 | 低 | 间接 | 低 | **P2** |
| — 环境因素(IP/邮箱) | 运维 | 高 | 长期 | 高 | **P2**(根因修复后再优化) |

## 七、验证方法

1. **修复后立即验证字段映射**:注册一个账号,检查 `OpenAIBackendAPI(access_token)._build_fp()` 返回的 `oai-device-id` 是否等于 `account["device_id"]`,`user-agent`/`impersonate` 是否来自 `account["fingerprint_profile"]`。
2. **抓包对比**:修复前后分别触发一次 `fetch_remote_info`,对比请求头——修复前应看到 Edge 143 + zh-CN + 随机 device,修复后应看到 Chrome 145 + en-US + 持久化 device。
3. **存活率对比**:修复根因 1-2 后,用现状(机房 IP + 临时邮箱)注册 10 个,观察 24h 存活率。若显著提升,证明代码 bug 是主因;若仍低,再优化环境因素。
